# Optional member activity history
This is a separate first-party history of successful account actions and browser-reported screen visits. It is not an authoritative telecom record. Do not use it as administrator access auditing. Guest use and signing in work without opting in. Once a signed-in member opts in, **future** events are recorded. The first sign-in before consent is not backfilled.

## Activation
The database migration has been applied to the hosted Feelody project. Set the same fresh random 32-byte or longer secret (e.g. a password manager's 64 hex characters) in Supabase Vault as `feelody_activity_writer` and Cloudflare Pages Production **Secret** as `FEELODY_ACTIVITY_WRITER`. Redeploy Pages. Never use the Resend key, a service-role key, chat, or git for the value. Preview environments should use a separate DB and secret. Rotation or provider failures may cause gaps; activity recording must never block sign-in/out. Opt-out deletes even when the writer is disabled.
## Retention & review before activation
Only account UUID, event, server timestamp and a fixed screen enum are stored. Navigation changes within an open editor do not log diary dates. The hourly job at minute 7 deletes rows aged three calendar months; monitor cron.job_run_details for failures. Revocation and account closure delete activity from the live database. Backups, Supabase Auth logs, Cloudflare logs and Google/Microsoft telemetry have separate retention. Verify vendor settings and retention independently, including backup expiry and deletion after restore.
The three-month interval is a product choice here, not a finding that Korean telecommunications retention rules apply. Before enabling: identify the operator/privacy contact, confirm legal basis and foreign transfer arrangements (including hosting in Australia, subprocessors and contact details), publish applicable notices and verify analytics/ads consent separately. Closing an account currently hides profiles and diary rows; it is not permanent erasure. Define and implement a justified hard-erasure deadline for those records before representing that account data is erased. Check whether separate administrator access auditing obligations apply.
