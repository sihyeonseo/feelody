# 실험 기록

## 데이터와 비교 기준

- 2000~2025년 곡 카탈로그 원본 2,600행 → 고유 곡 ID 2,262개 → 가사 누락 ID 18개 제외 → 2,244곡. 같은 가사를 묶으면 2,242개 그룹이다. 검색 순위 단위는 가사 그룹, 표시 단위는 곡이다.
- 고전 일기는 개발용으로 제공된 편집·해석 자료다. 역사적 진위나 번역 정확성을 검증하는 과제가 아니다. 소규모 파일럿에서는 모델명을 가리고 곡의 감정 적합성을 평가했다.
- 현대 일기 142편에는 각각 참고곡이 한 곡씩 있다. 상황 범주별로 고정된 수를 ID 해시 순으로 보류해 개발 114편, 보류 28편으로 나눴다. 아래 결과는 개발셋이다. 보류셋의 성능 또는 일반 사용자 취향을 대표하지 않는다.
- B1과 B3는 같은 E5-small 인덱스를 사용한다. B1은 일기(query)–가사(passage)의 코사인, B3는 각 텍스트(passage)가 감정 문장(query)들과 갖는 유사도를 중심화·정규화한 뒤 계산한 코사인이다. B2는 별도 한국어 BGE 기반 비교였다.

## 개발셋: 참고곡 검색

| 방법 | 1위 | 상위 5 | 상위 20 | 상위 50 |
|---|---:|---:|---:|---:|
| B1 | 4/114 | 8/114 | 12/114 | 16/114 |
| B3 | 2/114 | 4/114 | 7/114 | 13/114 |

상위 50 기준 둘 다 성공 7편, B1만 성공 9편, B3만 성공 6편, 둘 다 실패 92편. B1 후보만 재정렬하면 나머지 98편의 지정 참고곡은 복구할 수 없다. 이것이 그 98편의 1위 곡이 감정적으로 부적합하다는 뜻은 아니다. [개별 순위 및 모델·인덱스 정보](../reports/modern_dev.json)

## 실제 추천과 응답시간

고전 일기 블라인드 파일럿(10편, 채점 항목 20개): 0점 어긋남, 1점 일부만 일치, 2점 대체로 일치, 3점 매우 잘 맞음. 1위 적합률(2점 이상)은 B1 30%, B3 40%; 감정 평균은 1.0점과 1.5점이다. 같은 파일럿에서 두 모델의 1위 후보만 대상으로 순위 역수의 합을 썼을 때 적합률은 30%였다. 독립된 추가 평가가 아니다. 공동 1위는 일기 안에서 가사 그룹별 동일 가중치로, 일기 간에는 일기별 동일 가중치로 집계했다. [집계](../reports/research_summary.json)

[로컬 벤치마크](../reports/local_benchmark.json)는 서버 프로세스 시작 후 첫 결과 10,499.96ms, 준비 후 두 요청 31.43ms와 21.57ms, 50ms 간격 샘플링 기준 최대 RSS 663.5MiB였다. DB 누적 로그가 아니라 벤치마크 실행이 만든 측정값이다. 1회 실행이므로 서비스 p95나 동시 접속 성능은 추정하지 않는다.

## 재현 순서

다음은 모두 저장소 루트에서 실행한다. 데모 대신 실제 2,244곡 인덱스를 사용한다.

1. 현대 일기 CSV를 로컬 `data/modern.csv`에 둔다. 필요한 열은 `diary_id,situation_type,text,target_song_id`다. **기존 142편 전용** 분할 규칙이라 임의의 CSV에는 맞지 않는다.

       python feelody_modern_baseline.py --csv data/modern.csv

2. E5-large는 같은 개발 일기·가사·평가 코드를 유지하고 검색 인코더를 비교하는 다음 실험이다. 이 저장소에 large의 실측 결과는 없다. 원래 CSV와 가사 그룹 파일이 기존 기록과 동일한 경우:

       python feelody_modern_large.py --csv data/modern.csv --baseline reports/modern_dev.json

   방금 만든 기준 결과로 비교하려면 `--baseline` 뒤에 그 JSON 파일을 지정한다. large용 가사 벡터는 별도 캐시에 저장하며 실행을 재개할 수 있다. 모델 교체 판단은 참고곡 순위뿐 아니라 실제 1위 추천의 블라인드 감정 평가로 한다.

3. 블라인드 평가를 새로 할 때는 `data/pilot.json`에 본인이 평가할 일기를 `{"D01":"일기 본문"}` 형식으로 준비한다.

       python feelody_blind_pilot.py prepare --diaries data/pilot.json

   생성된 `feelody_pilot01/review.html`에서 일기와 가사를 보고 `ratings.csv`에 0~3을 입력한 뒤 `python feelody_blind_pilot.py score`를 실행한다. 채점 전 모델 정답키는 열지 않는다. 이 파일럿의 B1/B3 1위만 대상으로 순위 결합을 실험하려면 이어서 `python feelody_rank_choice.py`를 실행한다. 공개용 B3와 파일럿은 내장 일기 본문을 분리했으므로 과거 정답키 대신 같은 공개 코드로 새로 만든 키를 쓴다.

4. 초기 B2 비교 코드의 명령은 `python feelody_compare.py build-b2`, 이어서 `python feelody_compare.py compare --diaries data/comparison.json`이다. 입력은 `{"diaries":[{"diary_id":"D01","text":"일기 본문"}]}` 형식이다.

## 결과를 검산하려면

`python verify_reports.py`는 표준 라이브러리만 사용해 개발셋 행별 순위에서 위 표를 다시 계산하고 저장된 지표·분할과 비교한다. 모델 추론을 재실행하는 검사는 아니다.
